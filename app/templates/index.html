RAG Evolution & Multi-Constraint Retrieval

From Static Pipelines to Autonomous Agents

RAG addresses LLM hallucinations and outdated knowledge. Gao et al. (2023): Three evolutionary paradigms. Our contribution: First comparative study on multi-constraint recommendation (3-5 simultaneous requirements).

Three Generations of RAG

Naive RAG (First Generation)

Pipeline: Query → Embedding → Top-K Vector Search → LLM Generation. Strength: Fast (~500ms), low cost. Limitation: Single-vector compression loses nuance; struggles with complex, multi-faceted queries requiring constraint satisfaction.

Advanced RAG (Second Generation)

Innovations: HyDE (Gao et al., 2022) generates hypothetical ideal documents to bridge the semantic gap; cross-encoder reranking provides 15-30% precision gains via full query-document attention. Limitation: Still passive—cannot decompose multi-step queries or enforce hard constraints.

Agentic RAG (Third Generation)

Paradigm shift: ReAct framework (Yao et al., 2022) enables autonomous agents to reason (plan next action), act (invoke specialized tools), and reflect (self-correct). Handles multi-constraint queries via tool chaining (e.g., mood → runtime → history filters). Trade-off: 5-10x latency, but 80%+ constraint satisfaction on complex queries.

Core Techniques

HyDE (Query Expansion)

Generates hypothetical "ideal answer" to user query, then embeds this expanded context. Bridges gap between terse queries and detailed documents. Used in our Advanced RAG.

Cross-Encoder Reranking

Joint encoding of [query, document] pairs enables full token-level attention. Reranks top-20 candidates for precision. Too slow for first-stage retrieval over large corpora.

ReAct Agents (LangChain)

Iterative loop: Thought (reason about goal) → Action (call tool) → Observation (process result). Enables decomposition of complex multi-step queries. Powers our Agentic RAG.

Research Gap

Existing work optimizes single paradigms. No comparative study evaluates all three RAG generations on multi-constraint recommendation tasks with latency/cost trade-offs.

Experimental Setup

Evaluation Metrics & Dataset Configuration

CSR (Constraint Satisfaction Rate)

Satisfied Constraints / Total Constraints

Primary metric. Measures percentage of user requirements (mood, time, rating) successfully met.

P@5 (Precision at 5)

Relevant Items in Top 5 / 5

Percentage of the top 5 recommendations that meet the user's core criteria.

MMA (Mood Match Accuracy)

Mood Matches / Total Items

Accuracy of emotional tone matching (e.g., "Sad" query returns sad movies).

RFQ (Runtime Fit Quality)

1 - (|Item Time - Limit| / Limit)

How well content fits within the user's available time window.

Latency

Time(Query) -> Time(Response)

End-to-end wall clock time from request to final recommendation.

Cost

(Input + Output Tokens) * Price

Total API cost per query including embeddings and LLM generation.

Conclusion & Future Work

Summary of Findings and Future Research Directions

1

No one-size-fits-all: Different applications require different RAG architectures. Choose based on your constraints (latency, cost, query complexity).

2

Agentic systems shine with complexity: For multi-constraint, contextual queries, autonomous agents with tools dramatically outperform simpler approaches.

3

HyDE + Reranking is powerful: Advanced RAG achieves 85% of Agentic quality at half the cost and latency—excellent middle ground.

4

Evaluation is critical: Comprehensive metrics (relevance, latency, cost) and diverse test queries are essential for fair comparison.

5

Planning & Reflection matter: Agentic RAG's ability to plan steps and self-reflect significantly improves result quality on complex queries.

6

Future of RAG is agentic: As LLM costs decrease and latency improves, autonomous agent-based systems will become the standard for knowledge retrieval.
